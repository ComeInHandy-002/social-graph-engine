## 第7页: C++ 引擎 — 策略模式设计 (技术亮点1)

```
IGraphAlgorithm (抽象基接口)
  ├── IPathFindingAlgorithm   → execute(graph, start, target)
  │     ├── BFSAlgorithm         O(V+E)   最短步数
  │     ├── DijkstraAlgorithm    O((V+E)logV) 带权最短
  │     └── DFSAlgorithm         O(V+E)   回声室检测
  │
  ├── IScoringAlgorithm       → execute(graph)
  │     ├── PageRankAlgorithm    O(I·E)   节点重要性
  │     ├── BetweennessCentrality O(V·E) 中介中心性
  │     ├── KCoreAlgorithm       O(V+E)   k核分解
  │     └── ClusteringCoefficient O(V·d²) 聚类系数
  │
  └── ICommunityAlgorithm     → execute(graph)
        ├── LPAAlgorithm         O(I·E)   标签传播
        └── ConnectedComponents  O(V+E)   连通分量
```

**核心要点**:
- 新增算法只需实现对应接口, 不用改任何现有代码
- IPC 通信: Python subprocess 调 C++ → C++ JSON输出到stdout → Python 解析
- 手写 JSON 序列化器, 零第三方依赖 (protocol.h, 333行)

| 数据库 | 类型 | 存什么 | 为什么用它 |

## 第9页: 缓存策略设计 (技术亮点3)

```
请求进来
  │
  ▼
┌─────────┐    命中    ┌─────────┐
│ 查Redis  │─────────→│ 直接返回  │
└────┬────┘           └─────────┘
     │ 未命中
     ▼
┌─────────┐           ┌─────────┐
│ 分布式锁  │──获得锁──→│ 计算+回填 │
└────┬────┘           └─────────┘
     │ 未获得锁
     ▼
┌─────────┐
│ 等待+重试 │ (防缓存击穿)
└─────────┘
```

**5种失效模式**:
1. **版本失效** (主) — `sgp:graph:pagerank:v3`
2. **标签失效** — 批量标记过期
3. **TTL兜底** — 24小时自动过期
4. **Pub/Sub实时** — 通知所有节点刷新
5. **Admin API手动** — 管理员强制失效

**TTL jitter**: 随机 ±10% 偏差, 防止缓存雪崩

**LOD优化**:
- 近距离: 完整球体渲染
- 远距离: 点精灵降级 (nodeResolution = 16 → auto)

```
  Request
     │
     ▼
┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐
│  CORS   │→│  GZip   │→│ RateLimit│→│RequestLog│→│ Error   │→ Route
│跨域控制 │  │>1KB压缩 │  │三层限流  │  │结构化日志│  │Handler  │
└─────────┘  └─────────┘  └────┬────┘  └─────────┘  └─────────┘
                               │
                    ┌──────────┼──────────┐
                    ▼          ▼          ▼
                匿名10/min  登录60/min  API Key 300/min
```

**三层限流**: 基于 Redis Sorted Set 滑动窗口
**JWT认证**: Access Token 15分钟 + Refresh Token 30天
**慢查询告警**: 超过 500ms 自动记录
